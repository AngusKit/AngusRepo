### 1.3 依赖规则

**✅ 允许的依赖方向：**
- 接口层 → 应用层 → 领域层
- 基础设施层 → 领域层（实现接口）

**❌ 禁止的依赖：**
- 领域层不能依赖其他层（保持纯净）
- 基础设施层不能依赖应用层和接口层
- 应用层不能依赖基础设施层（通过领域层接口）

## 2. 分层架构详解

### 2.1 接口层（Interfaces Layer）

**职责：**
- 处理HTTP请求和响应
- 参数验证和格式化
- DTO/VO转换
- Swagger API文档

**包含组件：**
- `XxxRest.java` - REST控制器
- `XxxFacade.java` - 门面接口
- `XxxFacadeImpl.java` - 门面实现
- `dto/` - 数据传输对象
- `vo/` - 视图对象
- `assembler/` - 数据组装器

**关键特点：**
- 不包含业务逻辑
- 只负责HTTP协议相关处理
- 使用`@NameJoin`注解自动填充关联名称

### 2.2 应用层（Application Layer）

**职责：**
- 协调领域对象完成业务用例
- 事务管理
- 业务流程编排
- 数据查询和关联数据填充

**包含组件：**
- `cmd/` - 命令服务（写操作）
  - `XxxCmd.java` - 命令接口
  - `impl/XxxCmdImpl.java` - 命令实现
- `query/` - 查询服务（读操作）
  - `XxxQuery.java` - 查询接口
  - `impl/XxxQueryImpl.java` - 查询实现
- `converter/` - 应用层转换器

**关键特点：**
- Cmd层使用`@Transactional`管理事务
- Query层负责数据查询和关联数据填充
- 使用`BizTemplate`进行参数校验和业务处理（注意：如果门面层调用的Query和Cmd类方法，必须添加BizTemplate模版，非门面层调用的Query和Cmd类方法不需要添加BizTemplate）

### 2.3 领域层（Domain Layer）

**职责：**
- 核心业务逻辑
- 领域模型定义
- 业务规则
- 仓储接口定义

**包含组件：**
- `Xxx.java` - 领域实体
- `XxxRepo.java` - 仓储接口
- `XxxSearchRepo.java` - 搜索仓储接口（可选）
- `enums/` - 枚举类型

**关键特点：**
- 不依赖其他层（保持纯净）
- 定义仓储接口，不包含实现
- 包含业务规则和领域逻辑

### 2.4 基础设施层（Infrastructure Layer）

**职责：**
- 技术实现
- 数据持久化
- 全文搜索
- 工具类

**包含组件：**
- `persistence/mysql/` - MySQL实现
- `persistence/postgres/` - PostgreSQL实现
- `search/` - 搜索实现
- `job/` - 定时任务
- `util/` - 工具类

**关键特点：**
- 实现领域层定义的接口
- MySQL和PostgreSQL实现在不同目录
- 使用`@Repository`注解标记为Spring组件

## 3. 完整开发流程

### 步骤1: 创建领域实体（Domain Layer）

**位置：** `domain/xxx/Xxx.java`

**关键要点：**
- 继承`TenantAuditingEntity<Entity, Long>`（多租户+审计）或`TenantEntity<Entity, Long>`（仅多租户）
- 实现`identity()`方法返回主键
- 使用`@Transient`标记非持久化字段
- 使用`@Type(JsonType.class)`处理JSON类型字段

**示例：**

```java
@Entity
@Table(name = "git_issues")
@EntityListeners({TenantListener.class})
@Setter
@Getter
@Accessors(chain = true)
public class Issue extends TenantAuditingEntity<Issue, Long> {

  @Id
  private Long id;

  @Column(name = "issue_number", nullable = false)
  private Integer issueNumber;

  @Column(nullable = false)
  private String title;

  @Column(columnDefinition = "TEXT", length = 50000)
  private String description;

  @Column(nullable = false)
  @Enumerated(EnumType.STRING)
  private IssueState state;

  @Type(JsonType.class)
  @Column(name = "assignee_ids", columnDefinition = "json")
  private List<Long> assigneeIds;

  // 非持久化字段 - 用于临时存储关联数据
  @Transient
  private UserInfo author;
  
  @Transient
  private List<UserInfo> assignees;
  
  @Transient
  private LinkedHashSet<String> labels;

  @Override
  public Long identity() {
    return this.id;
  }
}
```

### 步骤5: 创建Assembler（Interfaces Layer）

**位置：** `interfaces/xxx/facade/internal/assembler/XxxAssembler.java`

**关键要点：**
- 静态工具类，提供静态方法进行转换
- `toCreateDomain()`: DTO → Domain（创建）
- `toUpdateDomain()`: DTO → Domain（更新）
- `toDetailVo()`: Domain → 详情VO
- `getSpecification()`: DTO → 查询条件

**示例：**

```java
public class IssueAssembler {

  // DTO → Domain（创建）
  public static Issue toCreateDomain(IssueCreateDto dto, Long ownerId) {
    Issue issue = new Issue();
    issue.setTitle(dto.getTitle());
    issue.setDescription(dto.getDescription());
    issue.setAuthorId(getUserId());
    issue.setState(IssueState.OPEN);
    issue.setType(dto.getType());
    
    // 设置初始计数
    issue.setCommentsCount(0);
    issue.setReactionsCount(0);
    
    // 设置标签
    if (dto.getLabels() != null && !dto.getLabels().isEmpty()) {
      issue.setLabels(new LinkedHashSet<>(dto.getLabels()));
    }
    
    // 设置指派人
    if (dto.getAssigneeIds() != null && !dto.getAssigneeIds().isEmpty()) {
      issue.setAssigneeIds(dto.getAssigneeIds());
    } else {
      issue.setAssigneeIds(Collections.singletonList(ownerId));
    }
    return issue;
  }

  // DTO → Domain（更新）
  public static Issue toUpdateDomain(IssueUpdateDto dto, Integer issueNumber) {
    Issue issue = new Issue();
    issue.setTitle(dto.getTitle());
    issue.setDescription(dto.getDescription());
    issue.setAuthorId(getUserId());
    issue.setType(dto.getType());
    issue.setIssueNumber(issueNumber);
    
    if (dto.getLabels() != null && !dto.getLabels().isEmpty()) {
      issue.setLabels(new LinkedHashSet<>(dto.getLabels()));
    }
    issue.setAssigneeIds(dto.getAssigneeIds());
    return issue;
  }

  // Domain → 详情VO
  public static IssueDetailVo toDetailVo(Issue issue, UserManager userManager) {
    IssueDetailVo vo = new IssueDetailVo();
    vo.setId(issue.getId());
    vo.setNumber(issue.getIssueNumber());
    vo.setTitle(issue.getTitle());
    vo.setDescription(issue.getDescription());
    vo.setState(issue.getState());
    vo.setType(issue.getType());
    
    // 设置关联数据
    vo.setAuthor(issue.getAuthor());
    vo.setLabels(issue.getLabels());
    
    if (issue.getAssigneeIds() != null) {
      Map<Long, UserInfo> userInfoMap = userManager.getUserInfoMapByIds(issue.getAssigneeIds());
      List<UserInfo> assignees = userInfoMap.values().stream().toList();
      vo.setAssignees(assignees);
    }
    
    vo.setCommentsCount(issue.getCommentsCount());
    vo.setReactionsCount(issue.getReactionsCount());
    
    // 设置审计信息
    vo.setTenantId(issue.getTenantId());
    vo.setCreatedBy(issue.getCreatedBy());
    vo.setCreatedDate(issue.getCreatedDate());
    vo.setModifiedBy(issue.getModifiedBy());
    vo.setModifiedDate(issue.getModifiedDate());
    
    return vo;
  }

  // DTO → 查询条件
  public static GenericSpecification<Issue> getSpecification(IssueFindDto dto) {
    Set<SearchCriteria> filters = new SearchCriteriaBuilder<>(dto)
        .rangeSearchFields("id", "createdDate")      // 范围查询字段
        .matchSearchFields("title", "description")    // 全文搜索字段
        .orderByFields("id", "createdDate", "title", "state")  // 排序字段
        .build();
    return new GenericSpecification<>(filters);
  }
}
```

### 步骤6: 创建应用层服务（Application Layer）

#### 6.1 命令服务（Cmd）- 写操作

**位置：**
- 接口: `application/cmd/xxx/XxxCmd.java`
- 实现: `application/cmd/xxx/impl/XxxCmdImpl.java`

**关键要点：**
- 命令接口定义写操作方法，参数和返回值使用Domain对象
- 实现类继承`CommCmd<Entity, Long>`获得基础CRUD能力
- 使用`@Service`注解
- 使用`BizTemplate`进行业务处理（参数校验 + 业务逻辑）
- 使用`@Transactional`保证事务性
- 重写`getRepository()`方法返回仓储

**示例：**

```java
// 命令接口
public interface IssueCmd {
  Issue create(String owner, String repo, Issue issue);
  Issue update(String owner, String repo, Issue issue);
  Issue close(String owner, String repo, Integer issueNumber, IssueCloseReason reason);
  Issue reopen(String owner, String repo, Integer issueNumber);
  void delete(String owner, String repo, Integer issueNumber);
}

// 命令实现
@Service
public class IssueCmdImpl extends CommCmd<Issue, Long> implements IssueCmd {

  @Resource
  private IssueRepo issueRepo;

  @Resource
  private IssueQuery issueQuery;

  @Override
  @Transactional(rollbackFor = Exception.class)
  public Issue create(String owner, String repo, Issue issue) {
    return new BizTemplate<Issue>() {
      Repo repository;

      @Override
      protected void checkParams() {
        // 参数校验
        repository = repoQuery.findAndCheck0(owner, repo, true, true);
      }

      @Override
      protected Issue process() {
        // 业务逻辑处理
        issue.setRepositoryId(repository.getId());
        Integer nextNumber = issueQuery.getNextIssueNumber();
        issue.setIssueNumber(nextNumber);
        
        // 保存Issue
        insert(issue);  // 继承自CommCmd的方法
        
        // 保存关联数据（如Assignee、Label等）
        if (issue.getAssigneeIds() != null && !issue.getAssigneeIds().isEmpty()) {
          issueAssigneeCmd.saveIssueAssignee(issue.getId(), issue.getAssigneeIds());
        }
        
        // 组装关联信息
        issueQuery.assembleDetailInfos(List.of(issue), List.of(repository));
        
        return issue;
      }
    }.execute();
  }

  @Override
  @Transactional(rollbackFor = Exception.class)
  public Issue update(String owner, String repo, Issue issue) {
    return new BizTemplate<Issue>() {
      Repo repository;
      Issue existing;

      @Override
      protected void checkParams() {
        repository = repoQuery.findAndCheck0(owner, repo, true, true);
        existing = issueQuery.findAndCheck(repository.getId(), issue.getIssueNumber());
      }

      @Override
      protected Issue process() {
        // 更新字段
        if (issue.getTitle() != null) {
          existing.setTitle(issue.getTitle());
        }
        if (issue.getDescription() != null) {
          existing.setDescription(issue.getDescription());
        }
        
        issueRepo.save(existing);
        
        // 更新关联数据
        if (issue.getAssigneeIds() != null) {
          issueAssigneeCmd.deleteByIssueId(existing.getId());
          if (!issue.getAssigneeIds().isEmpty()) {
            issueAssigneeCmd.saveIssueAssignee(existing.getId(), issue.getAssigneeIds());
          }
        }
        
        issueQuery.assembleDetailInfos(List.of(existing), List.of(repository));
        return existing;
      }
    }.execute();
  }

  @Override
  protected BaseRepository<Issue, Long> getRepository() {
    return this.issueRepo;
  }
}
```

#### 6.2 查询服务（Query）- 读操作

**位置：**
- 接口: `application/query/xxx/XxxQuery.java`
- 实现: `application/query/xxx/impl/XxxQueryImpl.java`

**关键要点：**
- 查询接口定义读操作方法
- 实现类使用`@Service`注解
- 使用`BizTemplate`进行业务处理（注意：如果门面层调用的Query和Cmd类方法，必须添加BizTemplate模版，非门面层调用的Query和Cmd类方法不需要添加BizTemplate））
- 支持全文搜索和标准查询两种模式
- 查询后批量设置关联数据（避免N+1问题）

**示例：**

```java
// 查询接口
public interface IssueQuery {
  Issue detail(String owner, String repo, Integer issueNumber);
  Page<Issue> list(GenericSpecification<Issue> spec, Pageable pageable,
      boolean fullTextSearch, String[] match);
  Issue findAndCheck(Long id);
  Issue findAndCheck(Long repositoryId, Integer issueNumber);
  void assembleDetailInfos(List<Issue> issues, List<Repo> repos);
}

// 查询实现
@Service
public class IssueQueryImpl implements IssueQuery {

  @Resource
  private IssueRepo issueRepo;

  @Resource
  private IssueSearchRepo issueSearchRepo;

  @Resource
  private UserManager userManager;

  @Override
  public Issue detail(String owner, String repo, Integer issueNumber) {
    return new BizTemplate<Issue>() {
      Repo repository;
      Issue issue;

      @Override
      protected void checkParams() {
        repository = repoQuery.findAndCheck0(owner, repo, true, false);
        issue = findAndCheck(repository.getId(), issueNumber);
      }

      @Override
      protected Issue process() {
        // 组装关联信息
        assembleDetailInfos(List.of(issue), List.of(repository));
        return issue;
      }
    }.execute();
  }

  @Override
  public Page<Issue> list(GenericSpecification<Issue> spec, Pageable pageable,
      boolean fullTextSearch, String[] match) {
    return new BizTemplate<Page<Issue>>() {
      @Override
      protected Page<Issue> process() {
        // 处理关联查询条件（如标签、指派人等）
        Set<Long> assocIssueIds = new HashSet<>();
        
        // 关联标签查询
        Set<String> labels = CriteriaUtils.findAllIdInAndEqualValues(spec.getCriteria(), "label", true);
        if (isNotEmpty(labels)) {
          Set<Long> issueIds = issueLabelRepo.findIssueIdsByLabelNames(labels);
          if (issueIds.isEmpty()) {
            return Page.empty(pageable);
          }
          assocIssueIds.addAll(issueIds);
        }
        
        if (!assocIssueIds.isEmpty()) {
          spec.getCriteria().add(SearchCriteria.in("id", assocIssueIds));
        }
        
        // 根据是否全文搜索选择不同的仓储
        Page<Issue> page = fullTextSearch
            ? issueSearchRepo.find(spec.getCriteria(), pageable, Issue.class, match)
            : issueRepo.findAll(spec, pageable);
        
        // 批量设置关联数据
        if (!page.isEmpty()) {
          List<Repo> repos = repoQuery.findByIds(
              page.stream().map(Issue::getRepositoryId).collect(Collectors.toSet()));
          assembleDetailInfos(page.getContent(), repos);
        }
        
        return page;
      }
    }.execute();
  }

  @Override
  public Issue findAndCheck(Long id) {
    return new BizTemplate<Issue>() {
      @Override
      protected Issue process() {
        return issueRepo.findById(id)
            .orElseThrow(() -> ResourceNotFound.of("问题「{0}」不存在", new Object[]{id}));
      }
    }.execute();
  }

  @Override
  public void assembleDetailInfos(List<Issue> issues, List<Repo> repos) {
    // 获取用户信息
    Set<Long> userIds = getUserIds(issues);
    Map<Long, UserInfo> userInfoMap = userManager.getUserInfoMapByIds(userIds);
    
    // 获取标签信息
    Set<Long> issueIds = issues.stream().map(Issue::getId).collect(Collectors.toSet());
    Map<Long, List<IssueLabel>> issueLabelMap = issueLabelRepo.findByIssueIdIn(issueIds)
        .stream().collect(Collectors.groupingBy(IssueLabel::getIssueId));
    
    // 组装仓库信息
    Map<Long, Repo> repoMap = repos.stream().collect(Collectors.toMap(Repo::getId, r -> r));
    
    // 批量组装详情信息
    for (Issue issue : issues) {
      if (issue.getAuthorId() != null) {
        issue.setAuthor(userInfoMap.get(issue.getAuthorId()));
      }
      if (issue.getAssigneeIds() != null) {
        List<UserInfo> assignees = issue.getAssigneeIds().stream()
            .map(userInfoMap::get)
            .collect(Collectors.toList());
        issue.setAssignees(assignees);
      }
      List<IssueLabel> labels = issueLabelMap.get(issue.getId());
      if (labels != null) {
        List<String> labelNames = labels.stream().map(IssueLabel::getName).toList();
        issue.setLabels(new LinkedHashSet<>(labelNames));
      }
      issue.setRepository(repoMap.get(issue.getRepositoryId()));
    }
  }
}
```

### 步骤7: 创建门面服务（Interfaces Layer）

**位置：**
- 接口: `interfaces/xxx/facade/XxxFacade.java`
- 实现: `interfaces/xxx/facade/internal/XxxFacadeImpl.java`

**关键要点：**
- 门面接口定义业务方法，返回VO对象
- 实现类使用`@Component`或`@Service`注解
- 注入`Cmd`（命令服务）和`Query`（查询服务）
- 使用`Assembler`进行DTO/Domain/VO转换
- 使用`buildVoPageResult()`构建分页结果
- 使用`getMatchSearchFields()`获取全文搜索字段
- 使用`@NameJoin`注解自动填充关联名称

**示例：**

```java
// 门面接口
public interface IssueFacade {
  IssueDetailVo create(String owner, String repo, IssueCreateDto dto);
  IssueDetailVo update(String owner, String repo, Integer issueNumber, IssueUpdateDto dto);
  IssueDetailVo close(String owner, String repo, Integer issueNumber, IssueCloseDto dto);
  IssueDetailVo reopen(String owner, String repo, Integer issueNumber);
  void delete(String owner, String repo, Integer issueNumber);
  IssueDetailVo getDetail(String owner, String repo, Integer issueNumber);
  PageResult<IssueDetailVo> list(String owner, String repo, IssueFindDto dto);
}

// 门面实现
@Component
public class IssueFacadeImpl implements IssueFacade {

  @Resource
  private IssueCmd issueCmd;

  @Resource
  private IssueQuery issueQuery;

  @Resource
  private RepoQuery repoQuery;

  @Resource
  private UserManager userManager;

  @Resource
  private ActivityCmd activityCmd;

  @NameJoin
  @Override
  public IssueDetailVo create(String owner, String repo, IssueCreateDto dto) {
    // 校验仓库
    Repo repository = repoQuery.findAndCheck0(owner, repo, true, false);
    
    // DTO → Domain
    Issue issue = IssueAssembler.toCreateDomain(dto, repository.getOwnerId());
    
    // 调用命令服务保存
    Issue saved = issueCmd.create(owner, repo, issue);
    
    // 记录活动
    activityCmd.createIssue(saved.getRepositoryId(), saved.getIssueNumber(), "opened");
    
    // Domain → VO
    return IssueAssembler.toDetailVo(saved, userManager);
  }

  @NameJoin
  @Override
  public IssueDetailVo update(String owner, String repo, Integer issueNumber, IssueUpdateDto dto) {
    Issue issue = IssueAssembler.toUpdateDomain(dto, issueNumber);
    Issue saved = issueCmd.update(owner, repo, issue);
    return IssueAssembler.toDetailVo(saved, userManager);
  }

  @NameJoin
  @Override
  public IssueDetailVo close(String owner, String repo, Integer issueNumber, IssueCloseDto dto) {
    Issue closed = issueCmd.close(owner, repo, issueNumber, dto.getReason());
    // 记录关闭Issue活动
    activityCmd.createIssue(closed.getRepositoryId(), closed.getIssueNumber(), "closed");
    return IssueAssembler.toDetailVo(closed, userManager);
  }

  @NameJoin
  @Override
  public PageResult<IssueDetailVo> list(String owner, String repo, IssueFindDto dto) {
    // 处理仓库ID
    if (!owner.equals("default") && !repo.equals("default-repo")) {
      Repo repository = repoQuery.findAndCheck0(owner, repo, true, false);
      dto.setRepositoryId(repository.getId());
    }
    
    // DTO → Specification（查询条件）
    GenericSpecification<Issue> spec = IssueAssembler.getSpecification(dto);
    
    // 查询数据
    Page<Issue> page = issueQuery.list(spec, dto.tranPage(),
        dto.fullTextSearch, getMatchSearchFields(dto.getClass()));
    
    // Domain → VO（分页结果）
    return buildVoPageResult(page, (it) -> IssueAssembler.toDetailVo(it, userManager));
  }
}
```

## 4. 各层详细规范

### 4.1 REST控制器规范

**职责：**
- 接收HTTP请求
- 参数验证
- 调用Facade服务
- 返回HTTP响应

**规范：**
1. **HTTP方法映射：**
   - `POST` - 创建资源
   - `GET` - 查询资源
   - `PATCH` - 部分更新资源
   - `PUT` - 完整更新资源或业务操作（如关闭、打开、状态更新）
   - `DELETE` - 删除资源
   
   **说明：**
   - 资源的基本信息更新：使用 `PUT /{id}`（如更新用户、应用、租户等基本信息）
     - **重要**：PUT接口使用**替换覆盖**语义，直接设置所有字段（包括null），不是部分更新
     - 必填字段处理：在DTO中添加验证注解，或在Assembler中使用`nullSafe()`方法设置默认值
     - 不可更新字段：某些字段（如code）创建后不可修改，在Assembler中保持existing的值不变
   - 状态更新操作：使用 `PUT /{id}/status`（如启用/禁用、上线/下线等状态变更，视为业务操作）
   - 其他业务操作：使用 `PUT /{id}/{action}`（如关闭、打开、锁定等）
   - 部分字段更新：使用 `PATCH /{id}`（仅当明确需要部分更新语义时）
     - PATCH接口使用部分更新语义，只更新非null字段

2. **HTTP状态码：**
   - `201 CREATED` - 创建成功
   - `200 OK` - 查询/更新成功
   - `204 NO_CONTENT` - 删除成功
   - `400 BAD_REQUEST` - 请求参数错误
   - `404 NOT_FOUND` - 资源不存在
   - `403 FORBIDDEN` - 无权限

3. **参数验证：**
   - 使用`@Valid`验证请求体
   - 使用`@ParameterObject`验证查询参数
   - 使用`@PathVariable`获取路径参数

4. **响应格式：**
   - 统一使用`ApiLocaleResult<T>`包装
   - 成功时使用`ApiLocaleResult.success(data)`
   - 失败时由全局异常处理器处理

### 4.2 Facade门面规范

**职责：**
- 协调应用服务
- DTO/VO转换
- 结果组装
- 关联数据填充

**规范：**
1. **方法命名：**
   - 与Cmd/Query保持一致
   - 使用业务术语（如`create`、`update`、`close`）

2. **数据转换：**
   - 使用`Assembler`进行转换
   - DTO → Domain → VO

3. **关联数据：**
   - 使用`@NameJoin`注解自动填充关联名称
   - 在Query层批量设置关联数据

4. **分页处理：**
   - 使用`buildVoPageResult()`构建分页结果
   - 使用`getMatchSearchFields()`获取全文搜索字段

### 4.3 Cmd命令服务规范

**职责：**
- 写操作（增删改）
- 业务校验
- 事务管理
- 业务流程编排

**规范：**
1. **事务管理：**

2. **业务处理：**

#### 4.4.1 统计方法返回VO规则

**规则说明：**
- **统计方法（getStats）**：允许在Query层直接返回VO对象
- **其他查询方法**：必须返回Domain对象，VO转换在Facade层处理

**原因：**
- 统计方法通常只涉及数据聚合和计算，不涉及复杂的业务逻辑
- 统计VO结构简单，直接在Query层构建可以简化代码
- 其他查询方法返回Domain对象，保持领域层纯净，便于复用

**示例：**

```java
// Query接口 - 统计方法返回VO
public interface AppQuery {
  // 普通查询方法返回Domain对象
  Application findAndCheck(Long id);
  Page<Application> find(GenericSpecification<Application> spec, PageRequest pageable,
      boolean fullTextSearch, String[] match);
  
  // 统计方法允许返回VO对象
  ApplicationStatsVo getStats();
}

// Query实现 - 统计方法直接返回VO
@Service
public class AppQueryImpl implements AppQuery {
  
  @Override
  public ApplicationStatsVo getStats() {
    return new BizTemplate<ApplicationStatsVo>() {
      @Override
      protected ApplicationStatsVo process() {
        ApplicationStatsVo stats = new ApplicationStatsVo();
        stats.setTotalApplications(applicationRepo.count());
        stats.setEnabledApplications(applicationRepo.countByStatus(ApplicationStatus.ENABLED));
        stats.setDisabledApplications(
            applicationRepo.countByStatus(ApplicationStatus.DISABLED));
        stats.setBaseApplications(applicationRepo.countByType(ApplicationType.BASE));
        stats.setBusinessApplications(applicationRepo.countByType(ApplicationType.BUSINESS));
        stats.setSystemApplications(applicationRepo.countByType(ApplicationType.SYSTEM));
        return stats;
      }
    }.execute();
  }
}

// Facade实现 - 统计方法直接返回Query的结果
@Component
public class AppFacadeImpl implements AppFacade {
  
  @Override
  public ApplicationStatsVo getStats() {
    // 统计方法允许在Query层直接返回VO对象
    return appQuery.getStats();
  }
  
  @Override
  public ApplicationDetailVo getDetail(Long id) {
    // 其他方法必须在Facade层进行Domain到VO的转换
    Application app = appQuery.findAndCheck(id);
    return ApplicationAssembler.toDetailVo(app);
  }
}
```

**注意事项：**
- 只有统计方法（`getStats`、`getOverview`等）可以在Query层返回VO
- 其他查询方法（`find`、`detail`、`findAndCheck`等）必须返回Domain对象
- 统计VO应该放在`interfaces/xxx/facade/vo/`目录下

## 6. 最佳实践

### 6.1 分层原则

1. **严格分层：**
   - 每层只调用下一层
   - 不跨层调用
   - 保持依赖方向正确

2. **职责清晰：**
   - REST层只处理HTTP协议
   - Facade层只做协调和转换
   - Cmd层只做写操作和事务管理
   - Query层只做读操作和数据查询
   - Domain层只包含业务逻辑

3. **依赖倒置：**
   - Domain层定义接口
   - Infrastructure层实现接口

### 6.2 数据转换

1. **统一使用Assembler：**
   - 所有DTO/Domain/VO转换都通过Assembler
   - 不在REST层直接操作Domain对象
   - 不在Cmd/Query层直接操作DTO/VO

2. **转换方法命名：**
   - `toCreateDomain()` - DTO → Domain（创建）
   - `toUpdateDomain()` - DTO → Domain（更新）
   - `toDetailVo()` - Domain → 详情VO
   - `toListVo()` - Domain → 列表VO
   - `getSpecification()` - DTO → 查询条件

3. **PUT接口更新规则（替换覆盖）：**
   
   **重要：PUT接口使用替换覆盖语义，不是部分更新**
   
   - **替换覆盖原则**：PUT接口应该直接设置所有字段（包括null值），而不是只更新非null字段
   - **必填字段处理**：
     - 方式1：在DTO中添加验证注解（如`@NotBlank`、`@NotNull`），确保必填字段不能为null
     - 方式2：在Assembler中使用`nullSafe()`方法，当DTO中为null时使用existing的值作为默认值
   - **不可更新字段**：某些字段（如code、id等）创建后不可修改，在更新时保持existing的值不变
   
   **示例：**
   
   ```java
   /**
    * <p>将更新DTO转换为领域对象（PUT接口：替换覆盖）</p>
    * <p>注意：code字段不可更新，保持existing的值</p>
    */
   public static Application toDomain(ApplicationUpdateDto dto, Application existing) {
     // PUT接口是替换覆盖，直接设置所有字段（包括null）
     // 对于必填字段name，如果DTO中为null，使用existing的值作为默认值
     existing.setName(nullSafe(dto.getName(), existing.getName()));
     existing.setDisplayName(dto.getDisplayName());  // 直接设置，包括null
     existing.setType(dto.getType());
     existing.setVersion(dto.getVersion());
     existing.setVersionType(dto.getVersionType());
     existing.setUrl(dto.getUrl());
     existing.setTags(dto.getTags());
     existing.setSortOrder(dto.getSortOrder());
     existing.setStatus(dto.getStatus());
     existing.setDescription(dto.getDescription());
     // code字段不可更新，保持existing的值不变
     return existing;
   }
   ```
   
   **错误示例（部分更新，不符合PUT语义）：**
   
   ```java
   // ❌ 错误：这是PATCH的语义，不是PUT
   public static Application toDomain(ApplicationUpdateDto dto, Application existing) {
     if (dto.getName() != null) {
       existing.setName(dto.getName());
     }
     if (dto.getDisplayName() != null) {
       existing.setDisplayName(dto.getDisplayName());
     }
     // ... 其他字段也使用if判断
     return existing;
   }
   ```
   
   **说明：**
   - PUT接口要求客户端提供完整的资源表示（即使某些字段为null）
   - 如果某些字段在更新时不应该被修改，应该在DTO中不包含这些字段，或者在Assembler中忽略它们
   - 必填字段必须保证不为null，可以通过验证注解或nullSafe方法实现

### 6.3 事务管理

1. **事务边界：**
   - Cmd层方法使用`@Transactional`
   - Query层通常不需要事务（只读）

2. **事务传播：**
   - 默认使用`REQUIRED`（加入现有事务或创建新事务）

3. **异常回滚：**
   - 使用`@Transactional(rollbackFor = Exception.class)`

### 6.4 查询优化

1. **避免N+1问题：**
   - 使用`@Transient`字段存储关联数据
   - 在Query层批量设置关联数据
   - 使用`assembleDetailInfos()`方法批量组装

2. **分页查询：**
   - 查询DTO继承`PageQuery`
   - 使用`PageRequest`进行分页
   - 返回`PageResult<T>`包装分页结果

3. **全文搜索：**
   - 创建`XxxSearchRepo`继承`CustomBaseRepository`
   - 使用`SearchCriteriaBuilder`构建查询条件
   - 通过`fullTextSearch`参数控制是否启用全文搜索

### 6.5 异常处理

1. **统一异常：**
   - 使用框架提供的异常类
   - `ResourceNotFound.of()` - 资源不存在
   - `ResourceExisted.of()` - 资源已存在
   - `ProtocolException.of()` - 协议异常

2. **异常信息：**
   - 使用国际化消息键，支持多语言
   - 异常信息包含参数占位符
   - **推荐使用`MessageKeys`定义消息键常量**（见8.5.2节）

**示例：**

```java
// 方式1：直接使用字符串消息（简单场景）
if (IssueState.CLOSED.equals(existing.getState())) {
  throw ProtocolException.of("问题「{0}」已经关闭", new Object[]{issueNumber});
}

// 方式2：使用MessageKeys常量（推荐，支持国际化）
@Resource
private MessageSource messageSource;

if (IssueState.CLOSED.equals(existing.getState())) {
  String message = messageSource.getMessage(
      MessageKeys.ISSUE_ALREADY_CLOSED,
      new Object[]{issueNumber},
      LocaleContextHolder.getLocale()
  );
  throw ProtocolException.of(message);
}
```

### 6.6 API文档

1. **Swagger注解：**
   - 控制器使用`@Tag`定义分组
   - 方法使用`@Operation`描述操作
   - DTO/VO字段使用`@Schema`描述

2. **HTTP状态码：**
   - 创建: `201 CREATED`
   - 更新: `200 OK`
   - 删除: `204 NO_CONTENT`
   - 查询: `200 OK`

## 7. 常见问题

### Q1: 何时使用 `TenantAuditingEntity` vs `TenantEntity`?

**A:** 
- 如果需要记录创建人、创建时间、修改人、修改时间，使用 `TenantAuditingEntity`
- 如果只需要多租户隔离，使用 `TenantEntity`

### Q2: 何时需要创建 `SearchRepo`?

**A:** 
- 当需要支持全文搜索功能时，创建 `XxxSearchRepo` 继承 `CustomBaseRepository`
- 在 `infra/search/` 目录下创建实现类（通常为MySQL实现）

### Q3: Cmd和Query如何选择?

**A:** 
- 写操作（增删改）放在Cmd层
- 读操作（查询）放在Query层
- 如果方法既读又写，优先放在Cmd层，Query层可以调用Cmd层的方法

### Q4: 如何处理关联数据?

**A:** 
- 在Domain实体中使用 `@Transient` 字段存储关联数据
- 在Query层查询后批量设置关联数据（避免N+1问题）
- 使用 `assembleDetailInfos()` 方法批量组装

### Q5: MySQL和PostgreSQL实现如何组织?

**A:** 
- MySQL实现在 `infra/persistence/mysql/` 目录下
- PostgreSQL实现在 `infra/persistence/postgres/` 目录下
- 两个目录下的结构保持一致，按业务模块组织
- 都继承领域层定义的接口
- Spring会根据配置自动选择使用哪个实现

### Q6: 如何处理复杂的关联查询?

**A:** 
- 在Query层的`list()`方法中处理关联查询条件
- 先查询关联表获取ID集合，再添加到主查询条件中
- 使用`CriteriaUtils.findAllIdInAndEqualValues()`提取关联查询条件

### Q7: 如何实现软删除?

**A:** 
- 在实体中添加 `deleted` 字段
- 重写仓储的 `delete` 方法，改为更新 `deleted` 字段
- 或使用JPA的 `@SQLDelete` 注解

### Q8: 如何处理枚举类型?

**A:** 
- 在Domain层定义枚举类
- 实体字段使用 `@Enumerated(EnumType.STRING)` 存储字符串值
- DTO/VO中直接使用枚举类型

### Q9: 如何实现权限控制?

**A:** 
- 在Cmd层的`checkParams()`方法中进行权限校验
- 使用`PrincipalContext`获取当前用户信息
- 抛出`ProtocolException`或`ResourceNotFound`异常

### Q10: 如何处理通知和活动记录?

**A:** 
- 在Cmd层或Facade层调用通知服务
- 使用`ActivityCmd`记录活动
- 使用`NotificationHelperCmd`发送通知

#### 8.5.2 MessageKeys（消息键常量）

**位置：** `domain/MessageKeys.java`

**作用：** 定义国际化消息键常量，用于统一管理错误消息、通知消息等，支持多语言。

**使用场景：**
1. **异常消息** - 在异常处理中使用消息键
2. **通知消息** - 在通知服务中使用消息键
3. **国际化支持** - 通过MessageSource获取多语言消息

**设计原则：**
- 消息键格式：`{模块}.{类型}.{操作}.{key}`
- 示例：`issue.create.error.title`、`notification.issue.created.title`

**使用示例：**

```java

  String ISSUE_CREATE_ERROR_DESCRIPTION = "issue.create.error.description";
  String ISSUE_NOT_FOUND = "issue.not.found";
  String ISSUE_ALREADY_CLOSED = "issue.already.closed";

// 2. 在异常处理中使用消息键
@Service
public class IssueCmdImpl extends CommCmd<Issue, Long> implements IssueCmd {

  @Resource
  private MessageSource messageSource;

  @Override
  @Transactional
  public Issue close(String owner, String repo, Integer issueNumber, IssueCloseReason reason) {
    return new BizTemplate<Issue>() {
      Issue existing;

      @Override

          String message = messageSource.getMessage(
              MessageKeys.ISSUE_ALREADY_CLOSED, new Object[]{issueNumber},
              LocaleContextHolder.getLocale()
          );
          throw ProtocolException.of(message);
        }
      }

      @Override
      protected Issue process() {
        // 业务逻辑
        return existing;
      }
    }.execute();
  }
}
```

#### 8.5.4 PrincipalContext（请求上下文）

# PrincipalContext 类作用总结

## 核心作用

PrincipalContext 是一个**线程级别的安全上下文管理类**，主要用于：

### 1. **身份认证与授权管理**
- 管理当前请求的认证主体（Principal）信息
- 提供用户身份、权限、租户等关键信息的统一访问入口
- 支持多租户系统的数据隔离

### 2. **请求上下文存储**
- 使用 `InheritableThreadLocal` 存储线程隔离的 Principal 对象
- 支持父子线程间的上下文传递
- 提供全局的 ConcurrentHashMap 用于存储请求级别的临时属性

### 3. **统一信息获取**
- 为业务代码提供标准化的上下文信息访问接口
- 减少重复代码，提高代码可维护性

#### 9.3.1 Query层全文检索实现检查

**判断是否需要全文检索：**
- [ ] 检查DTO中是否包含文本搜索字段（如name、description、title、keyword等）
- [ ] 检查业务需求是否需要对这些字段进行模糊搜索
- [ ] 如果不需要全文检索，可以跳过以下检查项

**如果需要全文检索，检查以下项：**

**领域层：**
- [ ] 创建`XxxSearchRepo`接口，继承`CustomBaseRepository<Entity>`
- [ ] 使用`@NoRepositoryBean`标记基础搜索仓储接口

**基础设施层：**
- [ ] 在`infra/search/`目录下创建`XxxSearchRepoMysql`实现类
- [ ] 实现类继承领域层定义的`XxxSearchRepo`接口
- [ ] 使用`@Repository`注解标记实现类

**应用层Query接口：**
- [ ] Query接口定义支持全文检索的`find()`方法：
  ```java
  Page<Entity> find(GenericSpecification<Entity> spec, PageRequest pageable,
      boolean fullTextSearch, String[] match);
  ```

**应用层Query实现：**
- [ ] 注入`XxxSearchRepo`搜索仓储
- [ ] 在`find()`方法中根据`fullTextSearch`参数选择仓储：
  ```java
  Page<Entity> page = fullTextSearch
      ? xxxSearchRepo.find(spec.getCriteria(), pageable, Entity.class, match)
      : xxxRepo.findAll(spec, pageable);
  ```
- [ ] 使用`BizTemplate`包装查询逻辑（注意：如果门面层调用的Query和Cmd类方法，必须添加BizTemplate模版，非门面层调用的Query和Cmd类方法不需要添加BizTemplate））

**接口层Assembler：**
- [ ] 在`getSpecification()`方法中配置全文检索字段：
  ```java
  Set<SearchCriteria> filters = new SearchCriteriaBuilder<>(dto)
      .matchSearchFields("name", "description", "code")  // 配置全文检索字段
      .rangeSearchFields("id", "createdDate")
      .orderByFields("id", "createdDate", "name")
      .build();
  ```
- [ ] 全文检索字段必须与数据库字段名一致
- [ ] 全文检索字段通常包括：name、description、title、content、code等文本字段

**接口层Facade：**
- [ ] 在`list()`或`find()`方法中调用`getMatchSearchFields()`获取全文检索字段：
  ```java
  Page<Entity> page = xxxQuery.find(spec, dto.tranPage(),
      dto.fullTextSearch, getMatchSearchFields(dto.getClass()));
  ```
- [ ] 确保`getMatchSearchFields()`返回的字段数组与Assembler中配置的`matchSearchFields`一致

```java
    Page<Application> page = appQuery.find(spec, dto.tranPage(), 
      dto.fullTextSearch, getMatchSearchFields(dto.getClass()));  // 获取全文检索字段
    return buildVoPageResult(page, ApplicationAssembler::toListVo);
  }
}
```
