# AngusRepo 仓库格式服务开发需求

## 文档说明

本文档为10种仓库格式（Maven、Docker、NPM、NuGet、PyPI、APT、YUM、Raw、Helm、Go）生成对应的后端服务开发需求提示词，用于指导后端开发团队按格式实现差异化的制品管理服务。

## 通用架构设计

### 格式服务抽象层

所有仓库格式服务共享统一的抽象接口，通过策略模式（Strategy Pattern）实现格式差异化处理：

```java
/**
 * 制品格式处理器接口 - 所有格式服务的顶层抽象
 */
public interface ArtifactFormatHandler {
    
    /** 获取支持的格式 */
    RepositoryFormat getFormat();
    
    /** 解析制品元数据 */
    ArtifactMetadata parseMetadata(InputStream inputStream, String fileName);
    
    /** 验证制品格式合法性 */
    ValidationResult validateArtifact(InputStream inputStream, String fileName);

    String generateStoragePath(ArtifactMetadata metadata);
    
    /** 生成制品访问URL */
    String generateAccessUrl(Repository repository, ArtifactMetadata metadata);
    
    /** 处理格式特有的API请求（如Maven的metadata.xml, Docker的manifest等） */
    ResponseEntity<?> handleFormatSpecificRequest(HttpServletRequest request, Repository repository);
    
    /** 生成客户端配置指南 */
    SetupGuide generateSetupGuide(Repository repository, String authToken);
    
    /** 获取格式特有的索引/元数据文件 */
    byte[] generateIndex(Repository repository);
}
```

### 格式服务注册中心

```java
@Component
public class FormatHandlerRegistry {
    private final Map<RepositoryFormat, ArtifactFormatHandler> handlers;
    
    public FormatHandlerRegistry(List<ArtifactFormatHandler> handlerList) {
        this.handlers = handlerList.stream()
            .collect(Collectors.toMap(ArtifactFormatHandler::getFormat, h -> h));
    }
    
    public ArtifactFormatHandler getHandler(RepositoryFormat format) {
        ArtifactFormatHandler handler = handlers.get(format);
        if (handler == null) {
            throw new UnsupportedFormatException("Unsupported format: " + format);
        }
        return handler;
    }
}
```

## 1. Maven 仓库服务

### 开发需求提示词

```
你是一名资深Java后端开发工程师，正在为AngusRepo制品仓库管理系统开发Maven格式仓库服务。

## 项目背景
AngusRepo是一个企业级制品仓库管理系统（类似Nexus/Artifactory），采用Spring Boot 3.x + JPA + MySQL/PostgreSQL架构，支持多租户。Maven仓库服务需要实现完整的Maven仓库协议兼容，支持hosted/proxy/group三种仓库类型。

## 技术要求
- Java 17+, Spring Boot 3.x, Spring Data JPA
- 遵循RESTful API规范，接口文档见项目docs/api-design/目录
- 多租户数据隔离（tenant_id）
- 审计字段：tenantId, createdBy, creator, createdDate, modifiedBy, modifier, modifiedDate
- 创建/更新接口返回完整实体，删除接口返回204

## 核心开发任务

### 1. Maven协议兼容层（MavenProtocolController）
实现标准Maven仓库HTTP协议，使得mvn/gradle客户端可以直接对接：

- **GET  /{repositoryName}/{path}** - 下载制品/获取metadata.xml
  - 路径格式：`/maven-releases/org/springframework/spring-core/6.1.0/spring-core-6.1.0.jar`
  - 支持.jar/.pom/.war/.ear/.aar等文件类型
  - 支持maven-metadata.xml生成和返回
  - 支持.sha1/.md5/.sha256/.sha512校验和文件
  - Group仓库需要合并多个成员仓库的metadata.xml
  - Proxy仓库优先检查本地缓存，未命中则从远程获取

- **PUT  /{repositoryName}/{path}** - 上传制品（仅hosted类型）
  - 验证仓库类型为hosted
  - 解析GAV坐标（groupId:artifactId:version）
  - 自动生成/更新maven-metadata.xml
  - 计算并存储校验和（SHA1/MD5/SHA256）
  - 支持SNAPSHOT版本的时间戳命名（如1.0-SNAPSHOT → 1.0-20250119.143000-1）

- **DELETE /{repositoryName}/{path}** - 删除制品（仅hosted类型）

- **HEAD /{repositoryName}/{path}** - 检查制品是否存在

## 2. Docker 仓库服务

### 开发需求提示词

```
你是一名资深Java后端开发工程师，正在为AngusRepo制品仓库管理系统开发Docker Registry格式仓库服务。

## 项目背景
AngusRepo是一个企业级制品仓库管理系统，需要实现Docker Registry HTTP API V2协议兼容，使docker push/pull/login命令可以直接使用。支持hosted/proxy/group三种仓库类型。

## 技术要求
- Java 17+, Spring Boot 3.x, Spring Data JPA
- 必须兼容Docker Registry HTTP API V2（https://docs.docker.com/registry/spec/api/）
- 多租户数据隔离（tenant_id）
- 审计字段标准化

## 核心开发任务

### 1. Docker Registry V2 API兼容层（DockerRegistryController）

必须实现以下Docker Registry V2标准API：

- **GET  /v2/** - API版本检查（必须返回200和Docker-Distribution-Api-Version: registry/2.0）
- **GET  /v2/_catalog** - 列出所有镜像仓库（支持分页：?n=100&last=xxx）
- **GET  /v2/{name}/tags/list** - 列出镜像所有标签
- **HEAD /v2/{name}/manifests/{reference}** - 检查Manifest是否存在
- **GET  /v2/{name}/manifests/{reference}** - 获取Manifest
  - reference可以是tag或digest
  - 支持Manifest V2 Schema2和OCI格式
  - Content-Type: application/vnd.docker.distribution.manifest.v2+json
  - 支持Manifest List（多架构镜像）
- **PUT  /v2/{name}/manifests/{reference}** - 上传Manifest（仅hosted）
  - 解析Manifest中的layer引用
  - 验证所有layer已上传
  - 自动创建/更新tag
- **DELETE /v2/{name}/manifests/{reference}** - 删除Manifest
- **HEAD /v2/{name}/blobs/{digest}** - 检查Blob是否存在
- **GET  /v2/{name}/blobs/{digest}** - 下载Blob（layer/config）
  - 支持Range请求（断点续传）
- **POST /v2/{name}/blobs/uploads/** - 启动Blob上传
  - 返回Upload UUID和Location header
- **PATCH /v2/{name}/blobs/uploads/{uuid}** - 上传Blob数据块
  - 支持Chunked上传
  - 支持Monolithic上传
- **PUT /v2/{name}/blobs/uploads/{uuid}?digest={digest}** - 完成Blob上传
  - 验证digest匹配
- **DELETE /v2/{name}/blobs/uploads/{uuid}** - 取消上传
- **DELETE /v2/{name}/blobs/{digest}** - 删除Blob

### 2. Docker认证服务（Token Auth）
实现Docker Token Authentication规范：
- **GET /v2/token** - 获取Bearer Token
  - 参数：service, scope (如repository:library/nginx:push,pull)
  - 返回JWT token
- 支持docker login命令（Basic Auth → Token交换）
- 权限粒度：push/pull/admin

### 4. Docker Proxy Mirror
- 代理Docker Hub / GCR / Quay.io / ECR等远程Registry
- 透明缓存：首次pull从远程获取并缓存，后续直接返回本地缓存
- 缓存Manifest和Blob的TTL配置
- 支持Token Relay（传递认证到远程Registry）
- 远程Registry健康检查

### 5. Docker特有功能
- **镜像层去重**：Blob通过digest去重，跨仓库共享layer
- **垃圾回收（GC）**：清理未被任何Manifest引用的Blob
- **Webhook通知**：镜像push/pull/delete事件通知
- **镜像签名验证**：Notary/Cosign支持（可选）
- **漏洞扫描集成**：push后自动触发Trivy/Clair扫描

- Docker Registry V2 API兼容性是最高优先级，确保docker push/pull/login正常工作

- Docker客户端期望特定的HTTP头（Docker-Content-Digest, Docker-Distribution-Api-Version等）
- Group仓库需要合并多个Registry的_catalog和tags/list结果

## 4. NuGet 仓库服务

### 开发需求提示词

```
你是一名资深Java后端开发工程师，正在为AngusRepo制品仓库管理系统开发NuGet格式仓库服务。

## 项目背景
AngusRepo需要实现NuGet V3 API兼容（NuGet Server API），使dotnet CLI/Visual Studio/NuGet CLI可以直接使用。支持hosted/proxy/group三种仓库类型。

## 技术要求
- Java 17+, Spring Boot 3.x, Spring Data JPA
- 兼容NuGet V3 API（https://learn.microsoft.com/en-us/nuget/api/overview）
- 多租户数据隔离

## 核心开发任务

### 1. NuGet V3 API兼容层（NuGetRegistryController）

NuGet V3使用服务索引(Service Index)模式，所有API端点通过服务索引发现：

- **GET  /v3/index.json** - 服务索引（Service Index）
  - 返回所有API资源端点列表
  ```json
  {
    "version": "3.0.0",
    "resources": [
      {"@id": ".../query", "@type": "SearchQueryService"},
      {"@id": ".../registration/", "@type": "RegistrationsBaseUrl"},
      {"@id": ".../flatcontainer/", "@type": "PackageBaseAddress/3.0.0"},
      {"@id": ".../package", "@type": "PackagePublish/2.0.0"}
    ]
  }
  ```

## 10. Go 仓库服务

### 开发需求提示词

```
你是一名资深Java后端开发工程师，正在为AngusRepo制品仓库管理系统开发Go Module Proxy仓库服务。

## 项目背景
AngusRepo需要实现Go Module Proxy Protocol兼容（GOPROXY协议），使go命令可以通过GOPROXY环境变量直接使用。支持hosted/proxy/group三种仓库类型。

## 技术要求
- Java 17+, Spring Boot 3.x, Spring Data JPA
- 兼容Go Module Proxy Protocol（https://go.dev/ref/mod#module-proxy-protocol）
- 支持Go Checksum Database协议（可选）
- 多租户数据隔离

## 核心开发任务

### 1. Go Module Proxy API（GoModuleProxyController）

Go Module Proxy使用简单的HTTP GET API：

- **GET  /{module}/@v/list** - 列出模块所有版本
  - 返回纯文本，每行一个版本号
  - 版本格式: v1.0.0, v2.1.0-beta.1

- **GET  /{module}/@v/{version}.info** - 获取版本信息
  - 返回JSON: {"Version": "v1.0.0", "Time": "2025-01-19T14:30:00Z"}

- **GET  /{module}/@v/{version}.mod** - 获取go.mod文件
  - 返回纯文本go.mod内容

- **GET  /{module}/@v/{version}.zip** - 下载模块源码zip
  - ZIP格式，顶层目录为 {module}@{version}/
  - 遵循Go module zip规范

- **GET  /{module}/@latest** - 获取最新版本信息
  - 返回同.info格式的JSON

- **GET  /sumdb/{name}/lookup/{module}@{version}** - Checksum数据库查询（可选）

- **PUT  /api/v1/go/upload** - 上传Go模块（hosted类型自定义API）
  - 接收.zip文件和go.mod文件
  - 解析go.mod提取模块路径和依赖
  - 验证zip结构符合Go module规范

### 2. Go Module特有数据模型
```java
public class GoModuleMetadata {
    private String modulePath;        // github.com/user/repo
    private String version;           // v1.0.0
    private LocalDateTime timestamp;  // 版本发布时间
    private String goModContent;      // go.mod文件内容
    private String goVersion;         // Go版本要求
    private List<GoModuleDependency> require;    // 直接依赖
    private List<String> retract;     // 撤回的版本
    private List<GoModuleDependency> replace;    // 替换模块
    private List<GoModuleDependency> exclude;    // 排除模块
}

public class GoModuleDependency {
    private String path;              // 模块路径
    private String version;           // 版本
}
```

### 3. Go模块路径编码
Go Module Proxy要求对模块路径中的大写字母进行特殊编码：
- 大写字母A → !a（叹号+小写）
- 例如: github.com/Azure/azure-sdk → github.com/!azure/azure-sdk
- 需要在控制器层进行路径解码

### 4. Go Module ZIP规范
- ZIP文件顶层目录必须是 `{module}@{version}/`
- 文件路径使用/分隔（非OS路径分隔符）
- 不包含vendor目录
- 不包含.git等版本控制目录
- 单个文件不超过500MB
- 总大小不超过500MB

### 5. Go Proxy代理
- 代理Go官方模块代理（proxy.golang.org）
- 代理VCS（Git仓库）获取模块（高级功能）
- 缓存.info/.mod/.zip文件（不可变版本永不过期）
- 处理GONOSUMCHECK/GONOSUMDB私有模块
- 支持GOPRIVATE/GONOPROXY配置

### 6. 数据库表扩展
```sql

    id VARCHAR(64) PRIMARY KEY,
    tenant_id VARCHAR(64) NOT NULL,
    repository_id VARCHAR(64) NOT NULL,

    module_path VARCHAR(1000) NOT NULL,
    version VARCHAR(100) NOT NULL,
    timestamp TIMESTAMP NOT NULL,
    go_mod_content TEXT,
    go_version VARCHAR(20),
    require_deps JSON,
    retract JSON,
    replace_deps JSON,
    exclude_deps JSON,
    zip_path VARCHAR(1000),
    zip_size BIGINT,
    zip_hash VARCHAR(255),
    mod_hash VARCHAR(255),
    
    created_by VARCHAR(64) NOT NULL,
    created_date TIMESTAMP NOT NULL,
    modified_by VARCHAR(64) NOT NULL,

    INDEX idx_module_path (module_path),
    FOREIGN KEY (repository_id) REFERENCES repository(id) ON DELETE CASCADE
);
```

## 注意事项
- Go模块路径编码（大写→!小写）是Go Proxy协议的特殊要求
- Go模块版本是不可变的，一旦发布不能修改（除非retract）
- go.mod文件是纯文本，需要正确解析require/replace/exclude指令
- Go Module ZIP有严格的格式要求，需要验证
- GOPROXY支持多代理链式配置（逗号分隔），404应该传递到下一个代理
- 需要处理+incompatible版本后缀（v2+无go.mod的仓库）
- Major版本≥2时，模块路径包含/v2, /v3后缀
```
